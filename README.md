課題: 標準設定（Choice Action = create）では、参照先が見つからない場合に新しいレコードを作成します。

懸念点: Excel側の入力ミス（例：「総務部」を「総務ブ」と誤記）があった場合、B表に誤ったマスターデータが自動作成され、データ汚染が発生します。

対策: 原則として Choice Action = reject に設定し、不整合なデータはインポートさせない「ガード」が必要です。

3. 大文字・小文字、および前後の空白による影響
課題: データベース検索は形式に厳密です。

懸念点: Excel内の不要な空白（"Apple "）や、大文字小文字の差異（"google" と "Google"）により、同一データと見なされず紐付けに失敗する可能性があります。

対策: Field Map で「Case sensitive」のチェックを外す、またはインポート前にデータのクリーニング（トリミング）を実施する運用が必要です。

課題: 参照フィールドが複合主キーの一部である場合、その成否が重要になります。

対策: 主キーを構成する参照フィールドについては、紐付け失敗＝インポート失敗（reject）とする厳格な設定が推奨されます。

### 【中文版】ServiceNow ER 图功能 (Schema Map) 调查报告

**1. 调查对象**

* 功能名称：Schema Map (架构图)
* 性质：ServiceNow 平台标准自带功能 (Standard OOTB feature)

**2. 功能概要**
Schema Map 是用于查看数据库表之间关联关系的系统界面。它通过图形化的方式展示表结构，其显示内容和逻辑与标准的实体关系图 (ER Diagram) 一致。

**3. ER 图显示规范**
在 Schema Map 中，数据库的逻辑关系通过以下方式呈现：

* **实体 (Entity)：**
* 每个矩形方块代表数据库中的一张表 (Table)。


* **关系 (Relationship) - 重点：**
* **<span style="color:red;">红色连线 (Referencing)</span>**：代表**引用关系**（即数据库的外键 Foreign Key）。
* *示例：* 自定义表 A 中的 `Account ID` 字段指向 `Account` 表，图中会显示一条红线连接两者。


* **<span style="color:blue;">蓝色连线 (Extending)</span>**：代表**继承关系**（即父子表关系）。
* *示例：* `Linux Server` 表继承自 `Server` 表。




* **显示范围：**
* 支持配置“引用层级 (Reference Levels)”，可选择仅显示直接关联的表，或显示多层级关联的表。



**4. 结论**
经调查，ServiceNow 的 Schema Map 功能能够完整展示表与表之间的字段引用关系。
对于本项目中的自定义表（如 PII 项目表）及其关联的系统表，可以直接使用该功能生成并导出 ER 关系图，无需使用外部绘图工具。

### 【日本語版】ServiceNow ER図機能 (Schema Map) に関する調査報告書

**1. 調査対象**

* 機能名：Schema Map (スキーママップ)
* 区分：ServiceNow プラットフォーム標準機能 (Standard OOTB feature)

**2. 機能概要**
Schema Map は、データベース上のテーブル間の関連性を可視化する管理画面です。その表示内容とロジックは、一般的な実体関連図 (ER図) と同等です。

**3. 表示仕様 (ER図としての構成要素)**
Schema Map において、データベースの論理関係は以下のように表現されます。

* **実体 (Entity):**
* 各矩形ノードは、データベース内のテーブル (Table) を表します。


* **関連 (Relationship) - 重要:**
* **<span style="color:red;">赤色の線 (Referencing)</span>**: **参照関係**（外部キー / Foreign Key）を表します。
* *例:* カスタムテーブル A の `Account ID` フィールドが `Account` テーブルを参照している場合、赤線で接続されます。


* **<span style="color:blue;">青色の線 (Extending)</span>**: **継承関係**（親子関係 / Inheritance）を表します。
* *例:* `Linux Server` テーブルが `Server` テーブルを拡張（継承）している場合、青線で接続されます。




* **表示範囲:**
* 「参照レベル (Reference Levels)」の設定により、直接関連するテーブルのみ、または数階層先のテーブルまで含めるかを選択可能です。



**4. 結論**
調査の結果、ServiceNow の Schema Map 機能は、テーブル間のフィールド参照関係を正確に表示可能です。

A. フィールドの重み付け (Field Weights / Boosting) - 最重要

仕組み： テーブル内の各フィールドに対して、検索時の優先順位（重み）を設定します。

適用例： 「社員ID」や「氏名」フィールドの重みを 高 (High/50) に設定し、「備考」や「説明」フィールドを 低 (Low/1) に設定します。

効果： 検索時、IDや氏名が一致するレコードが、備考欄にキーワードが含まれるだけのレコードよりも上位に表示されます。

B. 同義語とゆらぎ補正 (Synonyms & Typo Handling)

仕組み： 用語の辞書マッピングや、誤入力の自動補正ルールを設定します。

適用例： 携帯 = スマホ = Mobile のように同義語を定義します。

効果： ユーザーの入力用語とデータベース上の登録用語が異なる場合でもヒット率を維持し、スペルミス（例：Laptap -> Laptop）も自動吸収します。

C. 検索結果の改善ルール (Result Improvement Rules)

仕組み： 特定のキーワードに対して、特定のレコードを強制的に「上位表示 (Promote)」または「非表示 (Block)」にします。

効果： 重要なドキュメントやレコードをピンポイントでユーザーに提示することが可能です。
